# Plan review: Quickshell notch shell
Verdict: PASS WITH CHANGES
Summary: The screens, state model and foundation are coherent, and there is no deadline, so scope can't fail the review. But the plan says it "replaces the bar entirely" while leaving out several things the old shell does today: the wallpaper and video renderer, the caffeine idle inhibitor, the system tray, a battery level while unplugged, and the Hyprland launch and keybind cutover. The reuse map also marks several modules "keep as is" that depend on `Visibilities`, which the plan replaces. There is also a layer-shell exclusive-zone trap the plan does not mention. MUST is underestimated by about 60%.

## Unnamed risks
- **The smoke test runs a second full shell on the live session.** Every `make check` (and the toolkit Stop hook) starts `qs -p shell/shell.qml` for 10 s while the daily shell runs. That briefly maps real surfaces with exclusive zones, so windows reflow. It also tries to register a second NotificationServer and PolkitAgent (only one is allowed per session), adds extra IdleMonitors, and may log errors that cause false smoke failures. Likelihood: high. Mitigation: add a `NOTCH_SMOKE=1` env (`//@ pragma` or `Quickshell.env`) that skips registering the notification server, polkit agent, idle monitors and exclusive zones in smoke runs.
- **Old bar and notch running together.** The plan keeps the old bar as a fallback. If both run, they fight over the notification DBus name, the polkit agent and idle locking, which can lock twice or suspend twice. Likelihood: medium. Mitigation: the cutover script stops one before starting the other. Document "never run both".
- **Shared state directory.** Both configs read and write `~/.local/state/quickshell/*.json` (idle, wallpaper, theme, security). Format drift during the port can corrupt the fallback's settings. Likelihood: medium. Mitigation: either share the files on purpose and freeze their formats, or use a `notch/` subdirectory.
- **Expanded states collide on narrow monitors.** The launcher plus description pane, or the expanded media + calendar, can overlap the OSD and corner surfaces on small external monitors. Likelihood: medium. Mitigation: define a max centre width token per monitor and test on the smallest monitor.
- **Edge cases in Hyprland's Lua dispatch bridge.** Launching apps through `execDetached` instead of `hl.dsp.exec_cmd` bypasses workspace rules, and the bridge syntax may change on the git build. Likelihood: medium. Mitigation: keep all dispatches in one `Hypr` service with a single wrapper function.
- **Burn-in from the static idle notch on OLED.** The date, rings and dot sit at fixed pixels on the top edge, even though permanent glow is ruled out. Likelihood: low–medium. Mitigation: slow 1–2 px pixel shift, or dim the idle text after N minutes without input.

## Questions for the user (max 5)
1. Is the system tray needed in v1 (for example a tray row in the control center), or are you OK losing tray access when the bar goes away? Why it matters: without it, minimise-to-tray apps can't be restored. My recommendation: MUST, as a compact icon row in the control center.
2. Should the notch take over wallpaper rendering (including video wallpapers) and the caffeine inhibitor, or is a static hyprpaper fallback acceptable? Why it matters: this decides the background item and whether the wallpaper command view works. My recommendation: reuse the old Background module as is.
3. How should battery level show while discharging? Why it matters: right now it is invisible at rest, with no low-battery warning. My recommendation: show it only below a threshold (for example 20%), plus a critical toast at 10%.
4. Which command views do you need on day one? Why it matters: deferring screensaver, security and webapp saves about 2 days. My recommendation: wallpaper, theme and keybinds as MUST; the rest as SHOULD.
5. Should notification history survive a shell restart or reboot? Why it matters: it changes the Notifs rewrite (persistence, cap). My recommendation: session-only, capped at 50.

Technical recommendations (no user input needed): finding 3 (one reserving surface, the rest Ignore); finding 13 (filter auto-repeat); finding 15 (queue keyed by id, with updates); use `Quickshell.Services.UPower` for Battery instead of `udevadm` + bash forks; use `DesktopEntry.execute()` or the `hl.dsp.exec_cmd` wrapper for launching apps; put the old `Paths.qml` hardcoded `quickshell/deadlock` path behind a token.
